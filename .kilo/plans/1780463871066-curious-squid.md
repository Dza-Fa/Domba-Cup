# Domba Cup Project Assessment

## Project Summary
Domba Cup is a client-side tournament/event website built with **Tailwind CSS** (via CDN + custom build), served with **live-server**. It contains 3 pages: landing (`index.html`), team registration (`registration.html`), and ticket purchase (`ticket.html`). Theme is dark (`#0d0d0d`) with red (`#ff3a1a`) and yellow (`#ffd600`) accents.

## Technology Stack
- **HTML5** + **Tailwind CSS** (CDN in `<head>` + compiled `dist/output.css`)
- **Font**: Inter (Google Fonts)
- **Icons**: Font Awesome 6.4
- **Dev tools**: `tailwindcss` CLI, `live-server` (port 3000)
- **No backend / framework detected**

## Page Structure
| File | Purpose | Size |
|------|---------|------|
| `index.html` | Hero, about, categories, schedule, FAQ, footer | ~262 lines |
| `registration.html` | Multi-step team registration form | ~587 lines |
| `ticket.html` | Ticket purchase/listing page | ~818 lines |

## Key Observations
- **Styling**: Mixes CDN Tailwind with compiled Tailwind + inline `tailwind.config` object in each HTML `<script>`. Config is duplicated across pages.
- **Performance**: Heavy SVG background textures (~90+ ticket SVGs); `index.html` has duplicate `<meta>` tags.
- **Color consistency flags**: `index.html` uses raw hex values (`#0d0d0d`, `#ff3a1a`, `#ffd600`) while `registration.html` and `ticket.html` define matching `brand`/`dark` colors in their inline Tailwind config.
- **Accessibility**: No skip links, some icon-only `<i>` elements without `aria-hidden` or labels.
- **Maintainability**: Large single-file HTML pages with inline config duplication; no component structure or CSS variables.

## Quick Start
```bash
npm install && npm start   # opens http://localhost:3000
```

## Risk Areas
1. Duplicate/divergent Tailwind config across 3 HTML files
2. Duplicate `<meta charset>` + `<meta viewport>` in `index.html` lines 4–9
3. Massive inline SVG asset folder with no lazy-loading strategy
4. No build pipeline beyond CSS; no JS bundling, testing, or linting
5. `live-server` is deprecated/unmaintained

# Backend Implementation Plan

## Goal
Add a backend to Domba Cup to support:
- Team registration form submission & storage
- Ticket purchase handling
- Basic admin dashboard to view submissions

## Proposed Stack (aligned with existing XAMPP environment)
- **Runtime**: PHP 8.x (already available via XAMPP)
- **Database**: MySQL / MariaDB (already available via XAMPP)
- **Server**: Apache (already available via XAMPP)
- **No external dependencies** — keeps the stack simple and deployable on local/standard shared hosting

## Architecture

```
Domba-Cup/
├── api/
│   ├── register.php          # POST endpoint for team registration
│   ├── purchase.php          # POST endpoint for ticket purchase
│   └── config.php            # DB connection, CORS, JSON helpers
├── admin/
│   ├── index.php             # Admin dashboard (list registrations + tickets)

│   └── tickets.php
├── assets/
│   └── db/
```

# Page Status & Issues (as of 2026-06-03)

## File Structure Note
Semua halaman utama telah diubah ekstensinya dari `.html` menjadi `.php`:
- `index.html` → `index.php`
- `registration.html` → `registration.php`
- `ticket.html` → `ticket.php`

Link internal di header/navigasi masih mengarah ke `.html` (misal `./registration.html`, `./ticket.html`). Ini perlu diperbarui ke `.php` agar navigasi tidak broken.

## Current Page Conditions

### 1. index.php
- **Status**: Paling stabil, tema gelap tetap terjaga
- **Tailwind config**: HANYA `fontFamily: Inter` di inline `<script>`; warna-warna lain menggunakan raw hex (`#ff3a1a`, `#ffd600`, `#0d0d0d`, `#111111`, dst.)
- **Risiko**: Rendering aman karena hex langsung dipakai, tidak tergantung konfigurasi warna custom
- **Aksi yang dibutuhkan**: Update link `.html` → `.php`

### 2. registration.php
- **Status**: PERINGATAN — sebelumnya terlihat putih karena:
  1. `<h2>...</<h2` (tag tidak tertutup benar) — SUDAH DIPERBAIKI
  2. Inline `tailwind.config` tidak mendefinisikan warna `brand`/`dark` — SUDAH DIPERBAIKI (dikembalikan)
- **Tailwind config**: Sekarang sudah ada `brand.red`, `brand.yellow`, `dark.900/800/700`
- **Risiko**: Setelah perbaikan, seharusnya tampilan gelap kembali. Jika masih putih, kemungkinan:
  - Browser cache (perlu hard refresh)
  - Ada tag HTML lain yang broken
  - Path asset (`./assets/registration/...`, `./assets/shared/...`) salah karena perubahan struktur folder
- **Aksi yang dibutuhkan**: Update link `.html` → `.php`, cek broken tag lain

### 3. ticket.php
- **Status**: Tailwind config sudah lengkap (`brand.dark/darker/card/red/yellow`)
- **Ukuran**: ~921 baris, cukup kompleks
- **Risiko**: Link internal masih ke `.html`
- **Aksi yang dibutuhkan**: Update link `.html` → `.php`

## Recommended Fixes (Prioritized)

### Priority 1: Broken Links
Ganti semua referensi `.html` ke `.php` di ketiga file agar navigasi antar halaman tetap berfungsi:
- `./registration.html` → `./registration.php`
- `./ticket.html` → `./ticket.php`
- `./index.html` → `./index.php`

### Priority 2: Validasi HTML Structure (khusus registration.php)
Cek dan perbaiki tag HTML yang belum tertutup dengan benar. Fokus di:
- `registration.php` baris ~239 (tadi ada `<h2` tanpa `>` penutup)
- Cek ada tidaknya tag pembuka tanpa pasangan penutup

### Priority 3: Konsolidasi Tailwind Config
Hindari duplikasi konfigurasi warna. Pertimbangkan memindahkan `tailwind.config` yang konsisten ke satu tempat (misal `tailwind.config.js` yang sudah ada) dan referensikan via CDN script di semua halaman.

### Priority 4: Path Assets
Pastikan path asset (`./assets/...`) tetap valid setelah migrasi ke `.php`. Karena lokasi file tidak berubah, path seharusnya tetap benar, tapi perlu diverifikasi.

## Out of Scope (sesuai kesepakatan sebelumnya)
- Admin login/auth
- Payment gateway (tetap upload bukti manual)
- Email notification
- Export CSV admin
